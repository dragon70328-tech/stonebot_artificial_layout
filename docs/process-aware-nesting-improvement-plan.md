# 任意 DXF 读图确认与统一工艺排板改进计划

日期：2026-09-18

## 1. 目标

将系统改进为面向任意 DXF 图纸的加工规划平台，主链路固定为：

```text
DXF 上传
  -> 通用读图与规格板候选识别
  -> 生成原位编号 DXF
  -> 用户对比、修正并确认
  -> 用户指定加工方法和排板参数
  -> 使用统一排板逻辑生成方案
  -> 用户查看排板 DXF
  -> 基于反馈生成新的排板版本
```

产品的核心优势不是某个固定模板，而是：

- 能处理来源和结构不同的 DXF；
- 能把识别结果透明地展示给用户；
- 能让用户原位修正并确认制造数据；
- 确认后使用统一、可复现的排板逻辑；
- 能根据用户查看排板结果后的反馈继续改进。

## 2. 不可动摇的产品边界

### 2.1 读图与排板分离

- 读图阶段负责找出规格板、孔洞、编号、材料和问题。
- 用户确认后生成不可变的已确认图纸快照。
- 排板阶段只能读取已确认图纸，不重新猜测图层和实体含义。
- 用户修改识别结果后，必须重新确认，不能静默沿用旧排板结果。

### 2.2 加工方法由用户确定

系统不替用户选择桥切、水刀或激光。用户选择加工方法后，系统只在该方法的硬约束内优化排板。

加工方法可以在查看排板结果后修改，但修改后生成新的排板版本，而不是修改旧 DXF。

### 2.3 排板目标统一

所有工艺使用统一的目标优先级：

1. 满足工艺硬约束；
2. 使用最少的大板；
3. 相同板数下选择最合适的切割方案；
4. 提高出材率和材料利用率；
5. 应用用户偏好作为最终平局条件。

不同工艺只能有不同的求解策略和校验规则，不能形成互不相干的业务逻辑。

## 3. 工艺规则

### 3.1 水刀和激光

- 允许任意角度旋转；
- 规格板边缘允许重合，可以沿任意轮廓共边；
- 是否追求共边由排板策略和目标决定；
- 大板尺寸、厚度、让尺等参数仍由用户输入。

### 3.2 桥切圆盘锯

- 规格板按固定角度旋转，通常只允许 `0/90/180/270`；
- 允许直线共边切割；
- 刀厚或有效刀缝宽度是必填工艺参数；
- 同一条共边刀路只计算一次；
- 刀缝占用实际材料宽度和高度，不能当作零件尺寸的一部分；
- 必须计入贯穿通切刀路、让尺和边缘修整；
- 排板边界必须使用用户输入的大板可利用尺寸。

桥切名义跨度的基本关系为：

```text
实际材料跨度 = 零件净尺寸外包络
             + 有效共边刀路数量 * 刀缝宽度
             + 必要的边缘修整损耗
```

实际材料跨度必须小于等于：

```text
大板可利用尺寸 + 用户允许使用的让尺
```

### 3.3 参数语义

前端和后端契约必须明确：

- 大板标称尺寸；
- 大板可利用尺寸；
- 大板厚度；
- 是否利用让尺；
- 让尺是总加量还是每边加量；
- 让尺长度和宽度；
- 桥切刀厚或有效刀缝宽度；
- 计算后的实际可用尺寸。

不能只显示一个没有口径说明的“让尺 30 mm”。

## 4. 统一数据契约

建议把现有 `NestingProfile` 中不断增加的零散参数拆分为独立契约。

### 4.1 SheetSpec

```text
nominal_width_mm
nominal_height_mm
usable_width_mm
usable_height_mm
thickness_mm
oversize_enabled
oversize_mode: total | per_side
oversize_width_mm
oversize_height_mm
```

### 4.2 ProcessPolicy

```text
process: bridge | waterjet | laser
rotation_policy
kerf_mm
allow_shared_edge
shared_edge_mode: straight | any_contour
min_gap_mm
other_process_constraints
```

### 4.3 ConfirmedDrawing

用户确认后的排板唯一输入，必须包含完整的不可变制造数据：

```text
外轮廓
孔洞
原始编号
最终编号
材料
厚度
来源实体
识别置信度
用户修正记录
确认摘要
```

当前 `ConfirmedDrawing` 只有 ID 和产物路径，需要扩展为可引用完整确认快照。

### 4.4 NestingRequest

```text
confirmed_drawing_id
sheet_spec
process_policy
target_sheet_count
feedback
seed
budget
```

### 4.5 NestingRevision

每次排板都产生不可变版本：

```text
零件位置和旋转角度
实际刀路
共边关系
刀缝占用
实际可用边界
大板数量
出材率
几何校验
工艺校验
用户反馈
算法版本和随机种子
```

## 5. 分阶段实施步骤

### 阶段 0：建立可回退基线

- 提交当前已验证的模板排板、门户前端和测试改动；
- 运行 Python 全量测试和前端测试；
- 后续每个阶段独立提交；
- 运行日志和本地密钥配置不进入 Git。

### 阶段 1：建立统一契约

- 新增 `SheetSpec`、`ProcessPolicy`、`NestingRequest`、`NestingRevision`；
- 扩展 `ConfirmedDrawing`，使其引用完整确认快照；
- 修改 `JobContext`、HTTP 请求模型和工具 schema；
- 停止继续向 `NestingProfile` 堆叠零散字段；
- 所有排板结果和报告记录完整输入快照。

验收标准：

- API、CLI、worker 和前端使用同一套参数字段；
- 同一份确认图纸和参数可以复现同一排板版本；
- 报告能完整还原当时的板尺寸、让尺、刀缝和工艺。

### 阶段 2：通用读图和原位确认

- 展开 `INSERT` 块引用并应用平移、旋转和缩放；
- 支持嵌套块和块内块；
- 统一处理 `LWPOLYLINE`、`POLYLINE`、`CIRCLE`、`ARC`、`SPLINE`、`ELLIPSE`；
- 处理单位、超大坐标、图层、线型和闭合容差；
- 识别外轮廓、孔洞、编号、材料和厚度；
- 输出识别置信度、问题原因和视觉高亮；
- 生成原位编号 DXF，支持用户修正编号、删除误识别件、补充漏识别件；
- 用户确认后生成 `ConfirmedDrawing`。

验收标准：

- 不同 CAD 来源和不同实体组织的 DXF 均能进入流程；
- 不能确定的对象不会静默消失，必须显示问题；
- 用户修正后的编号和零件关系可以稳定保存和复现；
- CGR45 文件哈希模板只作为回归基准，不再是任意 DXF 的主路径。

### 阶段 3：前端排板参数和确认

前端显示：

```text
加工方法
大板标称尺寸
大板可利用尺寸
大板厚度
让尺是否利用
让尺长度和宽度
让尺口径
刀厚或有效刀缝宽度
计算后的实际可用尺寸
```

行为要求：

- 选择桥切时，刀缝必填；
- 水刀和激光按对应工艺显示参数；
- 关闭让尺时保留数值但禁用输入，且不参与计算；
- 参数变化实时显示最终可用尺寸；
- 开始排板前显示参数确认卡；
- 用户确认后参数进入 `NestingRequest` 快照。

验收标准：

- 所有关键参数都能在前端看到和修改；
- 参数不会藏在命令行、提示词或 LLM 默认值中；
- 排板计算使用可利用尺寸和让尺后的有效尺寸，而不是标称尺寸。

### 阶段 4：统一排板引擎和工艺校验

- 建立统一的 `NestingEngine` 输入输出接口；
- 水刀和激光实现任意角度旋转、任意轮廓共边策略；
- 桥切实现直线共边、刀缝占用、通切刀路和可利用尺寸校验；
- 所有引擎共享边界、面积重叠、几何有效性和工艺校验；
- 桥切共边路径建立明确的数据结构，同一刀路不能重复计费；
- 排板 DXF 区分成品轮廓和加工刀路。

验收标准：

- 水刀/激光边界重合合法，面积重叠非法；
- 桥切刀缝不丢失、不重复计算；
- 桥切零件、刀路和让尺都不超过实际可用范围；
- 相同板数下可以比较共边长度、通切数量和切割可执行性。

### 阶段 5：反馈重排和版本比较

支持用户反馈：

- 尝试再减少一张板；
- 启用或关闭让尺；
- 修改让尺长度和宽度；
- 修改刀缝宽度；
- 更换加工方法；
- 调整旋转限制；
- 固定零件或大板；
- 调整最小间距和边缘距离。

验收标准：

- 每次反馈产生新的 `NestingRevision`；
- 旧版本不覆盖，可以比较板数、出材率和工艺指标；
- “减少一张”找不到可行解时，说明触发了哪些硬约束，而不是直接手工修改 DXF；
- 所有重排都从同一份已确认图纸开始。

### 阶段 6：生产化

- 完善 API、队列、worker、对象存储和租户边界；
- 增加真实浏览器端到端测试；
- 建立多来源 DXF 识别回归集；
- 建立识别准确率、编号匹配率、板数和出材率指标；
- 对 CGR45 等已验证案例保留回归测试，但不让模板绕过统一排板契约。

## 6. 当前代码对应改造点

- `src/dxf_reader.py`：通用实体、块引用和坐标变换解析。
- `src/drawing_profile.py`：从项目专用规则转向通用规则、候选画像和学习规则。
- `src/contracts.py`：新增并扩展确认图纸和排板输入契约。
- `src/constraints.py`：拆分 `SheetSpec` 和 `ProcessPolicy`，避免继续扩大 `NestingProfile`。
- `src/nesting.py`、`src/deepnest_engine.py`、`src/pairing.py`：统一接口并保留工艺专用求解策略。
- `src/postprocess.py`：只在不破坏工艺约束的前提下改变布局。
- `src/dxf_writer.py`：输出原位编号检查图和带刀路的排板图。
- `src/http_api.py`、`portal/nesting/`：提供参数表单、确认门、结果查看和反馈重排。
- `tests/`：增加任意 DXF、工艺参数、刀缝和版本重排测试。

## 7. 最高优先级

1. 先完成统一契约和 `ConfirmedDrawing` 快照；
2. 再完成通用读图和原位确认闭环；
3. 然后把板尺寸、让尺、厚度、刀缝纳入前端和后端；
4. 再统一水刀、激光和桥切的排板接口与校验；
5. 最后完善反馈重排和 SaaS 生产化。

任何新的排板优化，都必须建立在“已确认零件数据 + 用户指定工艺 + 完整参数快照”之上。
