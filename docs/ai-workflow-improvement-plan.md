# AI 智能排板工作流改进方案

> 本方案在现有 CLI 排板能力之上，增加“对话式引导、人类语言读图、逐步确认、进度显示、打断与回退”的完整交互流程。
> 适用形态：本地 Codex 使用、SaaS 网页端、云端部署。

---

## 1. 目标

让系统像一名排板工程师一样与用户协作：

1. 读取原始 DWG/DXF 图纸。
2. 用人类语言告诉用户“看到了什么”。
3. 对编号、让尺、排板参数等需求进行确认。
4. 生成原位确认 DXF，用户可反复提修改意见。
5. 用户确认后开始排板。
6. 排板完成后先报告大板数量，用户确认后再生成排板 DXF。
7. 用户确认排板结果后再进行后处理。
8. 每一步都有预估时间、水银进度显示、随时打断、回到上一步。

---

## 2. 当前系统与目标差距

| 当前系统 | 目标系统 |
|----------|----------|
| 只支持 DXF 输入 | 支持 DWG 转 DXF 后读取 |
| 排板前自动生成编号检查文件 | 由用户确认编号需求后再生成 |
| 排板完成后可选择确认板数 | 每个关键节点均可确认/打断/回退 |
| 后处理在排板结果输出前自动执行 | 先输出排板 DXF，用户确认后再后处理 |
| CLI 日志输出 | 前端阶段化进度、预估时间、水银条 |
| 参数由命令行指定 | AI 用自然语言理解并生成配置 |
| 规则散落在代码中 | 约束逐步外置为项目配置 |

## 3. 目标交互流程

### Step 0：上传/打开图纸
- 用户上传 `DWG` 或 `DXF`。
- 系统识别文件类型：
  - DXF 直接读取。
  - DWG 先通过服务端转换器转为 DXF，例如 ODA File Converter、LibreDWG 或商用转换服务。
- 输出：文件已接收、文件大小、预计读取时间。

### Step 1：读取图纸并用人类语言描述
系统读取后，向用户报告：

```text
我已完成图纸读取：
- 识别到 203 块台面板，306 个孔洞。
- 其中 203 块面板有原始编号，0 块需要自动编号。
- 有 143 处圆弧轮廓，已按弧线保留。
- 图层为 0，未发现需要排除的虚线/ZIGZAG 标记。
- 最大面板尺寸约 2540×1621mm，预计可以使用 3200×1800 大板。
```

描述内容至少包括：
- 实体总数、LWPOLYLINE/CIRCLE/TEXT/MTEXT/DIMENSION 数量。
- 封闭图形数量、孔洞数量。
- 原始编号数量、无编号面板数量。
- 圆弧/曲线数量。
- 尺寸范围、面积范围。
- 可能影响排板的异常：重复 handle、无效图形、可疑小图形。

### Step 2：确认编号规则
系统根据读图结果判断：
- 如果面板带原始编号：默认使用原编号。
- 如果存在无编号面板：询问用户是否自动编号，并请求编号要求。

用户可能的自然语言：
- “无编号的从 P-001 开始。”
- “按户型标签编号，例如 A厨房-01。”
- “不要无编号图形，只排有编号台面板。”

系统生成“编号方案预览”：
```text
编号方案：
- 原始编号：203 块
- 自动编号：0 块
- 编号规则：保留原编号，跳过无编号图形
```

用户确认后进入下一步。

### Step 3：生成原位编号 DXF
- 按用户确认的编号规则生成 `{文件名}_numbered_原位.dxf`。
- 图形位置与原图一致，不做平移、旋转。
- 图层结构：
  - `OUTER`：台面板外轮廓
  - `HOLES`：孔洞
  - `NUMBERS`：编号
- 每个面板使用 GROUP 组织，方便用户点选检查。

### Step 4：用户确认或提出修改
- 用户可以在前端查看 DXF，或下载后检查。
- 如用户提出修改意见，系统更新编号规则或读图配置，重新生成：
  - 修改编号格式
  - 调整搜索半径
  - 指定/排除图层
  - 排除线型
  - 修正孔洞归属
- 循环直到用户回复“确认”。

### Step 5：确认排板要求并启动排板
系统向用户确认：
- 大板名义尺寸与让尺
- 厚度
- 旋转角度
- 最小间距
- 分组规则
- 排板策略：最少板数/折中/快速预览
- 时间预算

示例：
```text
排板方案：
- 大板：3200×1600，让尺最大 3225×1625
- 旋转：0/90/180/270
- 间距：0mm
- 策略：最少板数
- 预计普通板约 121 张，让尺板约 5 张
- 预计耗时：约 3–8 分钟
是否开始排板？
```

### Step 6：排板执行与进度显示
- 排板在后台执行。
- 前端显示：
  - 当前阶段：读图 → 编号 → 排板 → 后处理
  - 当前子阶段：多轮贪心配置、LNS 优化、校验
  - 水银进度条：`0%–100%`
  - 预计剩余时间
  - 已运行时间
- 支持随时“暂停/打断”。
- 支持“回到上一步”修改参数后重跑。

### Step 7：排板完成，先报告大板数量
系统不立即生成最终文件，而是报告：

```text
排板完成：
- 普通板：121 张
- 让尺板：5 张
- 合计：126 张
- 出材率：87.08%
- 校验：通过
是否按此板数生成排板 DXF？
```

用户可选择：
- 确认生成 DXF。
- 修改参数重排。
- 回到编号步骤修改。

### Step 8：生成排板 DXF
- 用户确认板数后，系统生成 `{文件名}_nested_{尺寸}.dxf`。
- 此时不执行推边、对齐、间距等后处理。
- 提供文件预览/下载。

### Step 9：确认排板结果后进行后处理
系统询问：

```text
是否对当前排板结果进行后处理？
- 四边推板
- 边缘对齐
- 最小间距强制
```

用户确认后执行 `PostProcessor`：
- `maximize_edge_clearance`
- `align_edges`
- `enforce_min_gap`

后处理完成后生成最终文件：
- `{文件名}_nested_final_{尺寸}.dxf`
- `{文件名}_report_{尺寸}.json`

### Step 10：输出最终结果
- 展示最终文件、报告、出材率、校验结果。
- 支持回到排板前、后处理前、编号前重新操作。

## 4. 每步预估时间与进度模型

| 步骤 | 预估时间 | 进度显示重点 |
|------|----------|--------------|
| 文件上传/转换 | 数秒至数十秒 | 上传百分比、DWG 转换状态 |
| 读图分析 | 5–60 秒 | 实体解析数量、圆弧展开、层级构建 |
| 编号确认 | 即时 | 无进度，仅确认状态 |
| 原位 DXF 生成 | 5–30 秒 | 已写面板数/孔洞数 |
| 排板 | 数十秒至数十分钟 | 多轮配置进度、LNS 迭代进度、当前最优板数 |
| 板数确认 | 即时 | 无进度，等待用户操作 |
| 排板 DXF 生成 | 5–30 秒 | 写入实体数 |
| 后处理 | 数秒至数分钟 | 逐张板推边、对齐、间距处理 |
| 最终输出 | 5–30 秒 | DXF/JSON 写入 |

时间预估策略：
- 读图：按文件大小和实体数估算。
- 排板：按零件数、试验次数、LNS 预算估算。
- 后处理：按大板张数和面板数估算。
- 实际耗时持续更新，前端根据历史数据修正剩余时间。

## 5. 打断与回退设计

### 任务状态机

```text
idle
 -> uploading
 -> converting_dwg
 -> reading
 -> numbering
 -> preview_numbered
 -> waiting_user
 -> nesting
 -> nesting_done
 -> writing_nested
 -> waiting_postprocess
 -> postprocessing
 -> writing_final
 -> done
```

每个状态可进入：
- `cancelled`：用户主动打断。
- `failed`：系统错误。
- 前一稳定状态：用户选择“回退”。

### 打断策略
- 文件转换/读图/写文件：可立即取消。
- 排板：通过后台任务取消事件，或在子进程中终止进程。
- LNS 循环中加入检查点，响应取消请求。
- 后处理：逐张板处理，每张板之间检查取消事件。

### 回退策略
- 系统保留每个关键节点的中间文件：
  - 读图摘要
  - 编号 DXF
  - 排板原始结果
  - 后处理前结果
- 用户可回到：
  - 修改编号后重新生成确认 DXF
  - 修改排板参数后重新排板
  - 确认排板后重新生成 DXF
  - 确认后处理前重新后处理

## 6. AI 人类语言读图与交互

### 第一阶段：结构化摘要生成
- 使用现有 `dxf_reader` 输出结构化统计。
- 用规则模板生成自然语言描述。
- 优点：稳定、快速、无 AI 成本。

### 第二阶段：视觉辅助描述
- 将 DXF/DWG 渲染为 PNG。
- 使用视觉模型识别：
  - 面板数量与分布
  - 孔洞位置
  - 弧线/阴角
  - 标注编号
- 将视觉结果与结构化数据交叉验证。
- 优点：更接近“人类看图”。

### 第三阶段：对话式需求理解
AI 从用户自然语言中提取：
- 编号规则
- 大板尺寸与让尺
- 旋转、间距、纹理方向
- 分组规则
- 后处理开关
- 排板优化目标

提取结果必须显示为结构化表单，用户确认后才执行。

## 7. 让尺判断逻辑

让尺配置模型：

```yaml
sheet_spec:
  nominal:
    width: 3200
    height: 1600
  allowance:
    width_extra: 25
    height_extra: 25
  effective_max:
    width: 3225
    height: 1625
allowance_usage: auto
```

自动判断流程：
1. 对每块板计算所有允许旋转角下的包围盒。
2. 能放入名义尺寸的零件进入普通板池。
3. 不能放入名义尺寸、但能放入让尺尺寸的零件进入让尺池。
4. 让尺池零件继续使用“两两配对”策略，优先两张共用一张让尺板。
5. 报告：
   - `普通板 X 张`
   - `让尺板 Y 张`
   - `合计 X+Y 张`

- 支持编号确认、排板确认、后处理确认。

## 12. 关键风险与应对

| 风险 | 应对 |
|------|------|
| DWG 读取依赖转换器 | 服务端预装转换器；无法转换时提示用户上传 DXF |
| 排板任务耗时长 | 后台执行、可取消、进度推送 |
| AI 理解错误 | 所有 AI 结果必须转化为结构化确认表单 |
| 回退导致文件混乱 | 每个步骤保留版本化中间文件 |
| 多用户并发 | 任务队列隔离、租户隔离 |
| 后处理改变排板结果 | 后处理前保留原始排板结果，并允许回退 |
| 让尺判断不准确 | 结合包围盒预检与最终精确校验，输出让尺板数量明细 |
