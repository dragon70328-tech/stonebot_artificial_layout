# Agent 化改进实施计划

日期：2026-09-19

## 总原则

本项目的目标是**制造业域优先的 Agent 化**，不是建设通用 Agent 框架。

后续所有改进必须同时满足：

1. 不做不可解释的自动生产写入；
2. 确定性几何、排板和文件操作由 Python 工具执行；
3. AI 只生成结构化意图、配置、解释和受约束的下一步动作；
4. 人工确认门、artifact 血缘和回退能力不能被绕过；
5. 每一个架构改进都必须绑定可量化的业务指标。

### 2026-10-30 方向校准

本文原先把 Agent Loop 放在较靠后的通用阶段，但实际测试表明不同 Harness 的循环能力
差异明显，不能把业务正确性交给平台临场发挥。当前调整如下：

- Agent Loop 只负责用户交互和受约束动作选择；
- 识别、校验、修正、排板和交付闭环由 StoneBot Core 直接执行；
- Skill 与适配器不得复制业务逻辑；
- 同一套黄金案例必须在 Codex、DSH 和其他目标平台得到一致业务结果；
- 用户纠正形成候选画像包，而不是直接修改全局规则。

## 北极星指标

- 面板识别召回率；
- 孔洞识别准确率；
- 编号匹配准确率；
- 误识别面板数量；
- 排板硬约束违规数；
- 同输入重复执行一致率；
- 用户纠正次数；
- 从上传到确认完成的耗时；
- 学习模型上线后回退率和安全违规数。
- 跨平台黄金案例结果一致率；
- `blocked` 被误报为成功次数；
- 安装后 Runtime 自检通过率；
- 画像包回归通过率和回滚次数。

## 阶段 A：可验证的本体与 Harness 基线

### A1. 最小核心本体

交付：

- 统一实体：`Project`、`Job`、`DrawingSource`、`DrawingRevision`、`Artifact`、`Decision`、`ConfirmedDrawing`、`NestingRevision`、`LearningFeedback`；
- 明确关系：项目包含任务，任务包含图纸版本，版本产生 artifact，决策引用 artifact，排板只读取 ConfirmedDrawing；
- 定义生命周期：创建、读取、审图、确认、排板、后处理、完成、回退、取消、阻塞；
- 定义不变量：版本不可覆盖、确认后不可重新猜图、生产写入必须有人工确认。

验收：

- 每个实体都有 `id`、`schema_version`、来源摘要和创建时间；
- 任一结果都能追溯到输入、工具版本和用户决策；
- 建立本体契约测试，禁止反向依赖和悬空引用。

### A2. Schema Registry 与版本迁移

交付：

- 统一契约注册表；
- JSON Schema 导出；
- `v0.1 -> v0.2` 迁移样例；
- 契约兼容性检查；
- 废弃字段和新增字段规则。

验收：

- 同一工具不能在不同地方定义不同 schema；
- 旧版本 artifact 可以被读取或明确提示不可迁移；
- 契约变更必须有迁移测试。

### A3. Artifact 血缘与内容寻址

交付：

- artifact 记录：输入摘要、工具版本、参数快照、代码版本、输出摘要、父 artifact；
- 内容寻址 key；
- 回退等于切换 artifact_id，而不是覆盖文件；
- 排板 DXF、报告、纠正差异、学习反馈都进入血缘。

验收：

- 一次完成任务可以还原完整链路；
- 任意旧版本可重新激活和比较；
- 重复执行相同 job key 可以命中确定性缓存。

### A4. DXF 金标准 Harness

交付：

- 真实 DXF 金标准集；
- 每张图的期望面板数、孔洞数、编号、材料和排除对象；
- 图层扰动场景：全部放 0 层、随机改名、交换面板/孔洞层；
- 错误注入：缺编号、重复编号、超大坐标、开放轮廓、无效几何；
- 命令行 benchmark 和 JSON 报告。

验收：

- 一个命令运行完整基准；
- 输出识别准确率、编号准确率和硬约束违规数；
- CI 可检测识别回归；
- 同一输入、工具版本和 seed 得到一致结果。

## 阶段 B：Skill 化

### B1. Skill Manifest 和 Registry

每个 Skill 必须包含：

- `skill_id`、版本、描述、适用条件；
- 输入/输出契约；
- 允许调用的工具；
- 工艺约束和禁止事项；
- 失败处理和人工确认点；
- 示例、评测集、负责人和发布状态。

### B2. 首批核心 Skill

优先实现：

- `DXF 读图与审图 Skill`；
- `原位编号确认与纠错 Skill`；
- `桥切排板 Skill`；
- `水刀/激光排板 Skill`；
- `工艺约束校验 Skill`；
- `出材率与结果解释 Skill`。

验收：

- Skill 不直接写生产文件；
- Skill 只能调用白名单工具；
- 每个 Skill 有独立评测；
- Skill 可以被 Agent Loop 组合，但不能改变工艺流程。

## 阶段 C：受约束的自适应 Agent Loop

### C1. 上下文包

运行中的上下文包包含：

```text
当前目标
当前状态
已知实体和关系
已确认约束
工具执行结果
未解决问题
最近人工反馈
可执行动作
```

### C2. Observe -> Act -> Verify -> Replan

该循环首先在 StoneBot Core 内实现；外部 Agent 只参与对话和人工决策：

```text
读取状态
-> 选择下一步动作
-> 执行确定性工具
-> 验证输出
-> 失败/冲突/不确定时重规划
-> 到达人工门停止
```

### C3. 恢复策略

需要区分：

- 工具超时；
- 几何无效；
- 编号冲突；
- 画像不匹配；
- 模型与规则冲突；
- 用户拒绝确认；
- 资源耗尽；
- artifact 缺失。

每类问题都有固定恢复策略和最大重试次数，不能无限 Agent 循环。

外部 Harness 的模型循环能力只影响交互体验，不能改变核心闭环的通过标准。

## 阶段 D：生产边界

- DXF 解析进程/容器隔离；
- 文件大小、实体数、坐标范围、解析时间和内存限制；
- 每个工具声明 timeout、retry、idempotency、副作用和配额；
- 租户队列、配额、凭据隔离；
- 管理审计和模型运维告警；
- 训练数据脱敏、保留和删除策略；
- 生产写入的权限、审批和回滚链路。

## 实施顺序

```text
A1 最小本体
  -> A2 Schema Registry
  -> A3 Artifact 血缘
  -> A4 DXF Harness
  -> B Skill 化
  -> C Agent Loop
  -> D 生产边界
```

A1、A2、A3 可以并行设计，A4 是后续所有改进的验收基础。Skill 和 Agent Loop 不得早于 Harness 和本体基线。

## 每一步的完成定义

- 有明确契约；
- 有确定性执行路径；
- 有失败和回退路径；
- 有自动化测试；
- 有可观察指标；
- 有人工确认边界；
- 能被下一位开发者独立复现。
