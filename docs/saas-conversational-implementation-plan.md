# SaaS 对话式排板系统实施计划

## 1. 目标

将现有 Python 排板系统升级为云端 SaaS 对话式产品：

- 用户通过对话界面上传本地 DXF 文件
- LLM 理解用户语义，维护上下文，生成结构化排板意图
- 可信 Python 工具执行读图、审图、编号、排板、后处理、回看减板
- 系统生成排板 DXF、报告和必要说明
- 用户下载文件查看，并可在对话中继续调整大板尺寸或要求减少板数

## 2. 核心原则

- LLM 只负责：语义理解、上下文维护、计划生成、结果解释
- Python 工具只负责：读取 DXF、几何计算、排板、校验、生成 DXF/报告
- LLM 不得直接执行 Python、写生产文件或修改数据库
- 文件由可信工具生成，所有结果可审计、可复现
- 云端部署按“无状态 API + 对象存储 + 后台 worker”设计

## 4. 目标流程

1. 用户上传 DXF
2. 后端校验文件并保存对象存储
3. LLM 解析用户需求：
   - 大板尺寸
   - 加工方式
   - 是否允许旋转
   - 超大件尺寸
   - 是否回看减板
4. LLM 输出结构化工具调用
5. Python worker 执行读图、审图、编号、排板、后处理
6. 系统生成：
   - 排板 DXF
   - 编号原位 DXF
   - 排板报告
   - 后处理检查报告
7. 对话界面返回结果摘要、确认点和下载链接
8. 用户继续对话调整，LLM 更新配置并重新调用工具
9. 最终下载文件

## 4.5 统一门户设计

门户只做模块入口和路由，不承载具体业务逻辑。

前端路由：

- `/`：总界面，选择模块
- `/qa/`：标准问答
- `/nesting/`：识图排板
- 未来新增：`/module-x/`

后端路由：

- `/api/qa/*`：转发到标准问答服务
- `/api/nesting/*`：转发到识图排板服务
- `/health`：门户健康检查

模块配置示例：

```json
[
  {"id": "qa", "name": "标准问答", "path": "/qa/"},
  {"id": "nesting", "name": "识图排板", "path": "/nesting/"}
]
```

约束：

- 不合并两个 Python 项目
- 两个 FastAPI 服务独立运行
- 使用 Nginx/Caddy 统一转发
- 新增模块只增加配置，不修改门户框架

## 5.1 入门型实例部署策略

目标云服务器配置：

- CPU：`4 vCPU`
- 内存：`8 GB`
- 带宽：`10 Mbps`
- 流量：`1500 GB/月`

该配置可作为早期生产验证环境，但需控制重计算任务并发。

- Web API 和前端可以常驻，占用很小
- 排板任务必须放入队列，不在 HTTP 请求线程内执行
- 初始阶段运行 `1` 个排板 worker，稳定后再评估是否提高到 `2`
- 重计算任务使用独立进程，并设置内存和超时限制
- 数据库和对象存储尽量使用云托管服务，减少本机磁盘和内存压力
- 排板任务失败不能拖垮 API，队列需支持重试和取消

建议资源分配：

- Web API：`1 vCPU / 1 GB`
- 排板 worker：`2 vCPU / 4 GB`
- 预留：`1 vCPU / 3 GB` 给系统、数据库客户端和缓存
- Docker 内存上限不超过 `7 GB`，避免触发 OOM

建议参数：

- 对话预览：`budget=0` 或 `quick=True`
- 正式优化：`budget=60~180`
- 单个排板任务超时：`900~1800` 秒
- 单机同时排板：先 `1`，小任务稳定后可尝试 `2`
- 文件大小上限：建议 `50 MB`

带宽评估：

- `10 Mbps ≈ 1.25 MB/s`
- 水星 DXF 约 `11.5 MB`，上传或下载约 `9~10` 秒
- `1500 GB/月` 对当前 DXF/报告体量足够
- 真正瓶颈是排板 CPU，不是带宽

验收调整：

- 4 核 8GB 实例可同时处理少量对话和文件上传
- 排板任务排队执行，不阻塞界面
- 单个重任务运行期间，API 仍能返回任务状态和进度
- 云盘或对象存储不足时给出明确错误

## 7. 关键风险

- LLM 输出不稳定
  - 对策：工具白名单、阶段门禁、JSON Schema 校验
- 排板任务耗时长
  - 对策：独立 worker、任务队列、超时和取消机制
- 云端文件安全和租户隔离
  - 对策：对象存储隔离、API Key、审计日志
- DXF 文件复杂，错误输入导致任务失败
  - 对策：上传时做大小和格式校验，失败结果可读、可重试
- 回看减板是启发式，可能找不到全部减板方案
  - 对策：作为局部增强，不替代全局排板；结果需用户确认
