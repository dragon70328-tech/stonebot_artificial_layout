# 工作日志 2026-10-14

## 主题

按用户要求先出一份**带房号 + 材料号的原位 DXF**（材料号写在原位），
为此把"列头材料"做成画像能力：零件按质心 x 归列，材料号写进
`Part.material_group`，原位 DXF 新增 `MATERIALS` / `MATERIAL_HEADER` 图层。
本轮**不做排板**，也不改排板行为（`material_group_enabled` 仍为 false）。

---

## 一、列头材料（新能力）

### 画像新增字段（`src/drawing_profile.py`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `material_column_enabled` | `false` | 启用"每列一个楼层"的列头材料归属 |
| `material_layers` | `[]` | 材料标签所在图层（空则用 `number_layers`） |
| `material_label_pattern` | `材料\s*[:：]\s*(?P<materials>[A-Za-z0-9\-/、,;；\s]+)` | 材料标签正则 |
| `level_label_pattern` | `^(?P<level>L-\d+)\s*LEVEL$` | 楼层标签正则 |

### 新函数

- `collect_column_materials(doc, profile)`：收集楼层标签与材料标签，按 x 一一配对，
  返回列定义（`level` / `x_min` / `x_max` / `materials` / `material_group` /
  `label` / `point` / `height` / 可选 `warning`）。
- `column_material_for_x(columns, x)`：按质心 x 取列。
- `_text_left_edge()`：列边界锚点 = 文字视觉左边缘。

接线：`read_dxf_with_profile()` 在编号归属之后按质心 x 给每个零件写
`material_group` 与 `material_column`；`parts_data_to_recognized_drawing()`
把两者写进 `RecognizedPanel.properties`。

### 锚点必须是"标签左边缘"，不是包围盒中心（踩过的坑）

第一版用"楼层标签包围盒中心"当列边界，读 citizen 得到 **3524/3525 归列**，
`1002-01` 掉到列外，且 ST-6 变成 1544 件（旧统计是 1543）。

原因：citizen 的 `L-XX LEVEL` 是**左对齐 TEXT**（`halign=0`，实测
`L-10 LEVEL` insert=2170.8、bbox=(2170.8, 4467.9)），`insert.x` 就是文字左边缘，
也正好是该列零件的起始 x。用包围盒中心当边界会让每列整体右移半个字宽，
边界附近的零件被错分到相邻列。

改成左边缘后：**3525/3525 归列、0 件列外**，并与
`_analysis/material_usage_report.py`（10-13 的口径）逐件一致。

## 二、原位 DXF 增加材料号（`src/dxf_writer.py`）

`write_numbered_parts_dxf(parts, output_path, unit_system, material_headers=None)`：

| 图层 | 内容 |
|---|---|
| `OUTER` / `HOLES` / `CHECK_CLOSURE` | 同以前（轮廓 / 孔洞 / 未闭合提示） |
| `NUMBERS` | 零件编号（房号 + 序号，居中，白色） |
| `MATERIALS` | 零件材料号（绿色，居编号下方，**跟随零件进同一个 GROUP**） |
| `MATERIAL_HEADER` | 原图「材料：ST-x」列头标签，**按原坐标、原字高复写** |

`material_headers` 由 `collect_column_materials()` 给出（`text` / `point` / `height`），
`point` 取原标签**包围盒中心**——这样无论原文字是对齐还是居中，复写后视觉位置一致。
没有材料号的零件不写 `MATERIALS` 文本，两个材料图层也不会被创建
（既有调用方如 `main.py` / `tool_handlers.py` / `drawing_corrections.py` 行为不变）。

## 三、顺带修掉的一处会静默丢料的分支

`workflow.apply_material_grouping()` 以前只用 `material_group_for_number()`
（按编号前缀取材料）判断，citizen 的编号是 `1001-01` 这种房号，取不出前缀 →
**所有零件都会被判为"无允许材料"而整体跳过**。

现在优先保留读图阶段已写入的 `part.material_group`，取不到再回退编号前缀。
本轮 citizen 画像的 `material_group_enabled` 仍是 `false`，所以排板行为没有变化；
等用户确认材料归属后打开开关即生效。

## 六、ST-6 排板（用户当日口径）

用户口径：只排 **ST-6**、**桥式切割机**、大板 **3200x1600**、刀缝 **5mm**、
长宽让尺各 **30mm**、**让尺不作为可利用尺寸**。

### 新增 `--material`（分单排板）

不同材料绝不共板，一次只排一种料时需要过滤零件：

```
--material ST-6            # 只排 ST-6，其余零件跳过并在报告里写明
--material ST-6,ST-7       # 多种材料（各自成组）
```

- 材料组在整个图纸里都找不到时**直接报错并列出可用材料组**，不静默排空；
- 过滤后打印"材料筛选：只排 ST-6 —— N 件，跳过其他材料 M 件"，
  并提示本次输出目录里的原位 DXF / 排板 DXF / 报告只含该材料零件；
- 未开启 `material_group_enabled` 也能用（材料来自列头材料归属）。

### 命令与结果

```bash
python -X utf8 main.py "<citizen.dxf>" 3200 1600 20 \
  --drawing-profile citizen --material ST-6 --profile min_sheets \
  --kerf 5 --sheet-oversize 30,30 --cold-start --no-confirm
```

口径打印（与用户口径一致）：

```
大板口径: 标称 3200x1600mm，让尺 30x30mm（每维度总量），
          可利用尺寸 3200x1600mm（不含让尺），实物 3230x1630mm
刀缝校验: 允许 3230x1630mm（= 可利用尺寸 + 让尺），刀缝 5mm；
          DXF 外框 = 可利用尺寸 3200x1600mm
```

| 方案 | 板数 | 出材率 | 耗时 |
|---|---:|---:|---:|
| 贪心基线（`--no-beam --quick --budget 0`） | 153 | 84.75% | 540s |
| **生产版（束搜索 + LNS 180s + 回看）** | **148** | **87.62%** | 2144s |

理论最少 130 张（面积下界）。回看未发现可合并的板（`reduced_sheets=0`）。

### 独立校验（`_analysis/verify_nested_dxf.py`）

```
SHEET_BORDER 148 张，尺寸分布 {(3200.0, 1600.0): 148}
OUTER 1543 件；越界 0；重叠 >1mm^2 的 0 对
NUMBERS 1543（唯一 1543）；GROUP 1543 个，每组 2 个实体
报告零件清单 1543 件，与 DXF 编号集合一致: True
validation_errors = 0
```

补充统计：每板填充率最低 42.9% / 中位 86.5% / 最高 96.8%；低于 60% 只有 2 张
（尾板 147/148）。**每板件数中位数 = 12 = `beam_nesting._MAX_PIECES_PER_SHEET`
硬上限**，说明本图的板数受"每板最多 12 件"限制，这是下一步降板数的观察点
（尾板 148 号只有 2 件、填充率 42.9%，也是尾部卡死的典型形态）。

刀缝材料校验：54/148 张板存在贯穿通切（垂直 30 刀 / 水平 24 刀，
总刀长 X 150mm + Y 120mm），全部在允许的 3230x1630 之内 → 校验通过。

产物：`output/20261014_100157_citizen/`
（`citizen_nested_3200x1600.dxf`、`citizen_report_3200x1600.json`、
`citizen_postprocess_check.json`、`citizen_recognized.json`）。
排板 DXF 与报告已复制到桌面 `临时文件\citizen_ST-6_*.{dxf,json}`。

- 尾板（146~148 号：68.4% / 55.7% / 42.9%）仍是尾部卡死形态；
