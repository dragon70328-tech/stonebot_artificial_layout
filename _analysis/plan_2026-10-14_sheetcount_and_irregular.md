# 提案：台面板降板数 + 异形板排板能力（2026-10-14）

> 与 `docs/process-aware-nesting-improvement-plan.md`，并遵守 `docs/saas-architecture-goal.md`

## 一、已确认的事实（测量，不是推断）

| 结论 | 证据 |
|---|---|
| 我们的活以台面为主、几乎全是轴对齐件 | CGR45 轮廓边轴对齐 99.9%；citizen **100.0%**，含斜边件 **0/3525** |
| 因此 **NFP 对"降板数"的收益≈0** | NFP 的能力在斜边/弧边互锁，这两单没有对象；轴对齐件的可行点本就是轴对齐角点 |
| 板数缺口是**分组/调度**问题，不是贴合度问题 | CGR45 50→49 只要 +1.5pp，但 50 张布局**没有低于 60% 的板**（无干净尾板可并）→ 需跨板重组 |
| citizen 的缺口性质不同 | 尾板 42.9%/55.7% 很肥，但每板件数中位 **12 = `_MAX_PIECES_PER_SHEET` 硬上限** |
| 我们的"多轮重启"是假的 | 100 次布局（`--trials 10`）→ 与单次完全相同（52 张 / 70.15%） |
| "50 张"依赖具体的阶段组合与墙钟 | `--quick`（beam 400）→ 51；`--report-only`（跳过回看）→ 51；beam 1000 + 回看 → 50 |
| 两个阶段按墙钟截断 → 不可复现 | LNS `nesting.py:583`、回看 `nesting_reviewer.py:372` 的 `time.monotonic()` deadline |
| 成本超线性 | 203 件 1.78 s/次布局 → 1543 件 54 s/次（件数 7.6× → 耗时 30×） |
| **异形（水刀）路径没有搜索层** | `nest_parts_deepnest` 只有 BLF + 滑动压实 + 可选配对；`improve_budget`/`configs` 死参数；无回看 |
| 有石CAD 的做法可借鉴/不可借鉴的部分 | 见 `_analysis/rea_youshi/FINDINGS.md`、`BENCH_SPEED_VS_BREADTH.md` |

## 二、两条 KPI，分开演进

- **台面板**：KPI = 大板数（离散目标，有平台期）。搜索层要围绕"哪些件共享一张板"。
- **异形板**：KPI = 能否排入 + 单板填充/共边利用（不是板数）。
  两者共享基础设施（契约、口径、报告、校验），但**引擎与验收分开**。

## 三、阶段计划

### P0 确定性与口径（成本低，先做）

1. 排序键改为 `(板数, 尾板填充降序, 总浪费)`——把"尾板干净"变成显式目标
   （现在排序键里完全没有尾板项，50 张是撞出来的）。
2. 把 LNS / 回看的**时间预算换成确定性预算**（迭代数 / 候选数 / donor 数上限），
   时间只作为护栏；报告记录实际消耗 → 可复现、可审计（SaaS 要求）。
3. 掰正 `--quick` 语义：它应只影响预算，不应静默把 beam 宽度从 1000 降到 400
   （`src/workflow.py:648`）——同一张图因 flag 差一张板是交付事故。

**判据**：同参数连跑两次，板数、布局、报告耗时口径完全一致；
CGR45 在 `--quick` 与 full 下都不低于 50 张。

### P1 板数的真杠杆：跨板重组（核心投入）

4. 回看从"低填充板当 donor"升级为**跨板重组器**：目标是"清空一张板"，
   对最差 K 张板的零件做全局再分配（复用现有 LNS 子求解器），判决用几何不用面积。
   注意既有教训：子集压缩在 95%+ 填充需求下几何不可行，所以重组必须允许
   **三张及以上同时参与**，而不是只做 2→1。
5. citizen 专项：`_MAX_PIECES_PER_SHEET = 12` 改成可配置 / 按板面积自适应，做 A/B。
   （本图中位件数正好卡在上限，这是最便宜的一次实验。）

**判据**：CGR45 稳定 50（并观察 49 的可行性）；citizen 148 → 目标 146~147，
且每板填充分布不退化（不允许用"更碎的板"换板数）。

### P2 异形板能力（按"门槛 → 质量 → 几何升级"的顺序）

6. **一件图混排**：给 `Part` 增加加工方式（`processing_class`），来源可以是画像/图层/编号规则；
   台面走桥切、异形走水刀/激光，**一次成图**。现在 `NestingProfile.processing_class`
   是整单唯一开关，混排只能人工拆图（`AGENTS.md` 已记为待确认的架构改动）。
7. **给水刀路径补搜索层**：把桥切那套"子集重排 + 低填充板处理"移植过去
   （现在异形路径是单趟，`--budget` 完全无效）。这是异形件的**第一质量杠杆**，
   与 NFP 无关，且复用已验证的思路。
8. **然后是 NFP**，且只对非轴对齐件启用（按"是否存在斜边/弧段"门控），
   作为水刀路径的**候选位置生成器**；桥切路径不动。若全图轴对齐，NFP 直接跳过。

**判据**：给一份真实异形件图纸，量"能否排入 + 填充/共边"；
NFP 开启前后的对照必须建立在这份样本上，不能靠推理。

## 四、明确不做

- 不为降板数引入 NFP（数据不支持）。
- 不照搬有石CAD 的"有界候选（最近 20 件 / 每件 2000 次检查）"——那是他们近视的来源，
  也是他们需要人工挑方案来补的原因。
- 不把时间盐 / 多线程随机重启 / 人眼验收放进自动路径。
- 不默认打开模板复用（`--use-template`）——它固化历史布局，不体现算法能力。
- 不在没有异形样本前投入 NFP 实现。

## 五、需要用户提供

1. **一份真实异形件图纸**（弧边/造型边、水刀或激光），用于量化 P2 的收益；
   目前唯一的水刀验证样本是东莞奥特莱斯。
2. citizen 那 1982 件 `ST-7/ST-8` 的拆分规则（阻塞该单的剩余排板）。
3. 确认 P1 允许"三张以上板同时重组"的实验范围（会影响耗时量级）。
