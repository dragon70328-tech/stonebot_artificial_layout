# Worklog 2026-11-14

## INSERT block recognition

Implemented generic `INSERT` expansion for DXF recognition:

- nested blocks and nested INSERT references;
- MINSERT row/column arrays;
- translation, rotation and non-uniform scaling via ezdxf virtual entities;
- layer-0 and BYBLOCK layer/color inheritance;
- deterministic per-instance virtual handles;
- cycle, nesting-depth and expanded-entity guards that fail closed;
- recognition, numbering, thickness, audit, machine-readiness and preview use
  the same expanded entity view when block expansion is enabled.

Compatibility decision:

- unprofiled `read_dxf` expands blocks by default;
- project drawing profiles keep the historical direct-entity behavior unless
  `expand_insert_blocks=true` is explicit. This prevents annotation/symbol
  blocks in existing validated drawings from being treated as panels.

Source delivery:

- the source INSERT and block definition remain in the numbered DXF on layer
  BLOCKS;
- block-contained recognised parts receive OUTER/HOLES overlay geometry plus
  NUMBERS/material labels and a GROUP, because virtual instance handles do not
  exist in the source modelspace.

Validation:

- `tests/test_dxf_insert_blocks.py` covers nested blocks, non-uniform scaling,
  MINSERT, unprofiled defaults, cyclic blocks and source-copy delivery;
- existing Canada3L and Snow White validated cases remain unchanged.

  `test_validated_cases.py`; the harness now applies it;

  the gate counts panels carrying `original_number`. Current `776/1109` values
  are recorded as explicit `known_deltas`, with the 1109 value corroborated by
  the 2026-09-19 numbering repair log.
