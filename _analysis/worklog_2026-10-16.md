# 工作日志 2026-10-16

## 主题

读图能力被确立为项目核心竞争力（方向确认：只有分析图纸准确才能排板）。
落地"画像库积累流水线"的第一步：把"手写 drawing_profiles/*.json"变成
**自动提议 -> 人工核对 -> 登记入库** 三步。用户负责准备图纸与核对，
本轮交付提议/登记工具。

---

## 一、市场格局判断（战略背景）

按能力分三层：

1. **文件解析层**（ODA SDK / ezdxf / 看图工具）：成熟且商品化，无护城河；
   DXF-only 输入策略不变。
2. **行业 CAM 层**（EasySTONE / Alphacam Stone / 有石CAD / SigmaNEST 等）：
   "读图"= 几何清洗（闭合、去重、断线连接），编号/材料/归属全靠人工
   按约定清图——"图纸迁就软件"。
3. **语义理解层**：空档。最接近的成熟形态是广联达算量（规则库 +
   自动识别后人工校核）与酷家乐 AI 户型识别（置信度 + 人工修正 UX），
   均不做石材零件。

结论：护城河 = "软件迁就图纸"（读约定、报不准、最小确认），正是画像
机制的骨架。画像库是数据资产，配套两个收敛指标：**命中率上升、
新增画像率下降**。

## 二、画像提议工具（本轮交付）

### 新文件

| 文件 | 内容 |
|---|---|
| `src/profile_proposal.py` | `propose_profile()` / `validate_draft()` / `register_profile()` / `induce_label_pattern()` |
| `src/cli_profile.py` | CLI 胶水（`run_propose_profile` / `run_register_profile`） |
| `tests/test_profile_proposal.py` | 9 例：正则归纳 4 + 提议 3 + 登记 2 |

### CLI 用法

```bash
# 第 1 步：提议（只读图，不排板）
python main.py new.dxf --propose-profile [--profile-name xxx]
# 第 2 步：人工核对问题清单，必要时编辑草稿 JSON
# 第 3 步：登记（复算 expected_counts，写画像 + 已验证案例）
python main.py new.dxf --register-profile output/.../profile_draft_xxx.json [--force]
```

### 提议内容（全部由 DXF 结构统计自动产出）

- `panel_layer(s)`：实线封闭图形最多的图层（圆单列，按孔洞处理）；
- `number_layers` + `label_pattern`：短文本候选（2~15 字符、无空白、
  含数字、字符集受控）按字符类游程归纳最紧正则；同时含数字段与大写
  段时命名 `material`/`shape`，与 `_normalize_label` 约定对齐；
- `closed_tolerance`：未闭合多段线缝隙 p95（>5mm 判辅助线保持 0.01）；
- `small_area_threshold`：面积分布断层检测（相邻比值 >= 8 倍）；
- `build_hierarchy`：有 CIRCLE 即 True；`use_hatch`/`hatch_layer`：
  按 HATCH 存在与否；`exclude_linetypes`：全部非实线线型；
- `expected_counts`：候选参数经 `read_dxf_with_profile` 实读的结果，
  标注"待确认"。

产出三件套：草稿 JSON（可编辑）、提议报告（证据 + 实读 + 问题）、
终端问题清单（件数核对 / 编号覆盖率 / 排除线型 / 面积断层 / 孔洞层级 /
闭合容差）。

### 登记的硬门槛

- 登记前复算 expected_counts 并与草稿对比，**不一致默认拒绝**；
  `--force` 例外，并把"[登记警告]"写进 notes；
- 同名画像/案例已存在默认拒绝（`--force` 覆盖）；
- 写入：画像 JSON（含 fingerprint）+ `validated_cases/{name}.json`
  （case_id / source_sha256 / fingerprint / expected_counts）。

### 冒烟（CGR45final，已知真值 203/306/203）

`--propose-profile` 实读 **203 件 / 306 孔 / 203 编号**（与手写画像一致），
归纳正则 `^(?P<material>\d{3})\-(?P<shape>[A-Z]{1})$` 与手写
`^(?P<material>\d{3})-(?P<shape>[A-Z])$` 功能等价，编号图层 `['编号']`、
排除 `ZIGZAG`、`build_hierarchy=True`（153 CIRCLE）全部命中。
`--register-profile` 全链路验证后已清理测试产物（不入库）。

### 踩坑

测试矩形按"首点重复"画法时 `entity.closed=False`，初版统计把它算成
"未闭合、缝隙 0"，面积/图层统计整体漏掉。修复：gap<=1e-6 按闭合统计。

### 测试

全量快测 **476 passed**（基线 467 + 新增 9）。

## 三、下一步（按优先级）

## 四、规格板尺寸清单（用户当日新增需求）

需求：每次分析图纸后产出 **材料 × 区域 分类的规格板尺寸清单**（尺寸、
数量、表面处理、是否磨边、纹理走向；图纸未注明的留空）+ 原位 DXF，
作为人工审图参考。

### 交付

| 文件 | 内容 |
|---|---|
| `src/spec_list.py` | `build_spec_list()` 分组汇总 + `extract_annotations()` 图纸文字要求提取 + `write_spec_list_files()` |
| `src/models.py` | `Part` 新增 `material_column`（区域/楼层归属） |
| `src/numbering.py` | `assign_numbers` 透传 `material_column` |
| `main.py` | 主流程在 recognized.json / 原位 DXF 同批产出清单（排板前即可用，跟随 `--material` 过滤） |
| `src/cli_audit.py` | `--audit` 同批产出清单 + **原位 DXF**（审图流此前没有原位 DXF）；失败降级为警告不阻断审图主产物（与 overview SVG 同口径） |
| `tests/test_spec_list.py` | 6 例 |

### 产物

- `{stem}_规格清单.csv`（utf-8-sig，Excel/WPS 直接打开）：材料 | 区域 |
  长(mm) | 宽(mm) | 数量 | 单件净面积 | 面积小计 | 孔洞 | 编号 |
  表面处理 | 磨边 | 纹理走向 | 备注（异形件标"尺寸为外包络"），末行合计；
- `{stem}_规格清单.json`：分组 + 逐件明细 + 要求提取证据
  （`annotations_evidence` 保留原文供核对）。

### 口径

- 尺寸 = 外轮廓外包络跨度，长边在前（长>=宽），0.1mm 精度；
  异形件（外轮廓面积/外包络 < 0.98）在备注列标注；
- 表面处理/磨边/纹理走向：关键词扫描（抛光/圆边/顺纹等），**只提取
  图纸原文不做推断**，上下文窗口保留"不磨边"这类否定语境；
  未注明 = 空字符串；
- 材料 = `Part.material_group`（前缀或列头材料），区域 =
  `Part.material_column`（楼层列），都没有 = 空。

### 遗留

- 表面处理/磨边/纹理走向目前是图纸级关键词提取；若某项目按零件标注
  （如逐件边型标签），需加画像级正则（`surface_finish_pattern` 等），
  等真实样本出现再做；
- 审图流的清单生成会再读一次图（citizen 量级 +~90s）；后续可让
  `audit_drawing` 顺带返回 panels 消掉重复读；
- CSV 无多 sheet；若用户要 xlsx 排版（分材料 sheet、冻结表头），
  需引入 openpyxl 依赖（项目目前刻意用标准库读写 xlsx）。
