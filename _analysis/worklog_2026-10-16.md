## 一、市场格局判断（战略背景）

按能力分三层：

1. **文件解析层**（ODA SDK / ezdxf / 看图工具）：成熟且商品化，无护城河；
   DXF-only 输入策略不变。
2. **行业 CAM 层**（EasySTONE / Alphacam Stone / 有石CAD / SigmaNEST 等）：
   "读图"= 几何清洗（闭合、去重、断线连接），编号/材料/归属全靠人工
   按约定清图——"图纸迁就软件"。
3. **语义理解层**：空档。最接近的成熟形态是广联达算量（规则库 +
   自动识别后人工校核）与酷家乐 AI 户型识别（置信度 + 人工修正 UX），
   均不做石材零件。

结论：护城河 = "软件迁就图纸"（读约定、报不准、最小确认），正是画像
机制的骨架。画像库是数据资产，配套两个收敛指标：**命中率上升、
新增画像率下降**。

### CLI 用法

```bash
# 第 1 步：提议（只读图，不排板）
python main.py new.dxf --propose-profile [--profile-name xxx]
# 第 2 步：人工核对问题清单，必要时编辑草稿 JSON
# 第 3 步：登记（复算 expected_counts，写画像 + 已验证案例）
python main.py new.dxf --register-profile output/.../profile_draft_xxx.json [--force]
```

### 提议内容（全部由 DXF 结构统计自动产出）

- `panel_layer(s)`：实线封闭图形最多的图层（圆单列，按孔洞处理）；
- `number_layers` + `label_pattern`：短文本候选（2~15 字符、无空白、
  含数字、字符集受控）按字符类游程归纳最紧正则；同时含数字段与大写
  段时命名 `material`/`shape`，与 `_normalize_label` 约定对齐；
- `closed_tolerance`：未闭合多段线缝隙 p95（>5mm 判辅助线保持 0.01）；
- `small_area_threshold`：面积分布断层检测（相邻比值 >= 8 倍）；
- `build_hierarchy`：有 CIRCLE 即 True；`use_hatch`/`hatch_layer`：
  按 HATCH 存在与否；`exclude_linetypes`：全部非实线线型；
- `expected_counts`：候选参数经 `read_dxf_with_profile` 实读的结果，
  标注"待确认"。

产出三件套：草稿 JSON（可编辑）、提议报告（证据 + 实读 + 问题）、
终端问题清单（件数核对 / 编号覆盖率 / 排除线型 / 面积断层 / 孔洞层级 /
闭合容差）。

### 登记的硬门槛

- 登记前复算 expected_counts 并与草稿对比，**不一致默认拒绝**；
  `--force` 例外，并把"[登记警告]"写进 notes；
- 同名画像/案例已存在默认拒绝（`--force` 覆盖）；
- 写入：画像 JSON（含 fingerprint）+ `validated_cases/{name}.json`
  （case_id / source_sha256 / fingerprint / expected_counts）。

### 冒烟（CGR45final，已知真值 203/306/203）

`^(?P<material>\d{3})-(?P<shape>[A-Z])$` 功能等价，编号图层 `['编号']`、
排除 `ZIGZAG`、`build_hierarchy=True`（153 CIRCLE）全部命中。
`--register-profile` 全链路验证后已清理测试产物（不入库）。

### 关键设计

- 源图**按 sha256 内容配对**（线索来自 `*_recognized.json` 的 `input_digest`），
  绝不按文件名猜；优先级：显式 `--source` > 案例 source_sha256 > 历史运行摘要
  > 案例指纹记录的原图路径（按名称回找 + **指纹结构复核**，复核不过即放弃绑定）。
- **只补缺口**：缺 fingerprint 补指纹、缺 expected_counts 补件数、缺
  source_sha256 补摘要、缺案例建案例；**不一致只报告**——带件数的动作默认拦下，
  `--force` 才写并把"[回填警告]"留进 notes；补指纹/补 sha256 等身份类动作不受
  件数不一致影响。
- 一次读图同时产出件数与指纹；已"五件齐"的画像走快路径完全不读图。

## 六、三处不一致的根因定位 + 案例库进门禁

上一步体检出的三处"声明值与复算不一致"，本轮全部定位到根因。

### 方法（沙箱禁写 `.git` 时的历史复算）

`git worktree` 要写 `.git`，本机沙箱不允许。改用只读导出：

```bash
git archive -o tmp.tar <sha> src drawing_profiles && tar -xf tmp.tar -C <仓库外的目录>
python count_drawing.py <目录> mercury="<源图.dxf>" fuzhou_wanxiangcheng1="<源图.dxf>"
```

同一张源图在不同历史代码树里复算，二分定位改动点。探针脚本已归档到
`_analysis/bisect_2026-10-16/`（含用法与逐个脚本说明）。

### 复算证据（水星 / 福州万象城1）

| 代码树 | 时间 | 水星 | 福州万象城1 |
|---|---|---:|---|
| `06a9a96` | 08-20（画像登记当时） | 1258 | 133 / 36 |
| `8c700df` | 09-02 | 1258 | 37 / 15 |
| `fda608e` / `eed02d4` | 09-19 | 1258 | 49 / 248 |
| **`49da243`** | **09-19（容差分离修复）** | **1243** | **143 / 268** |
| `4f96884` / HEAD | 09-25 / 10-16 | 1243 | 143 / 268 |

登记当时的基线**都能复现**（水星 1258、福州 133/36），所以不是"当年记错"。

### 结论一：水星 15 件被静默丢弃（回归）

`49da243` 只改了 `src/dxf_reader.py` 16 行，把去重/裁剪的清理容差与闭合容差
分开（方向正确：福州那种 `closed_tolerance: 1000` 的画像，旧码拿 1000mm 去
去重会毁掉几何）。但它把**"末点落在已有边上 ⇒ 兜成闭合"**这条*判定*也钳到了
0.01mm，于是覆盖了画像声明的 `closed_tolerance`：

- 实体 `11DA7`（`F-3厨房-01`，L 形 1620x2540 台面）8 个顶点，`v7` 距 `v1`
  仅 **0.0309mm**（CAD 收口误差）→ 旧码（0.1mm）读出 1 件，现码读 0 件；
- 15 件同型（6 件 `F1-卫生间-*` 1.30x2.54m、9 件 `F-厨房/F-3厨房-*`
  1.62x2.54m），**都已分配房号编号**，且内部不含其他零件（不是房间轮廓）；
- 最小复现已固化为 `tests/test_validated_cases.py::test_open_loop_with_last_vertex_on_edge_is_recovered`。

修复方向：闭合判定用画像的 `closed_tolerance`，清理（去重/裁剪）保持收紧到
0.01mm —— 这正是那次提交标题说的"分离"，只是漏了这条判定。

### 结论二：福州万象城1 多出 10 件越界件（回归）

现算 143 件的图层分布暴露了根源：

| 图层 | 件数 | 画像态度 |
|---|---:|---|
| `ST-01水刀` / `ST-02整砖` / `ST-12整砖` | 28 / 86 / 19 = **133** | `panel_layers`，应提取 |
| `F-地材造型线` | 5 | 画像描述明确"不排板" |
| `ST-02算量` | 4 | 画像 notes 明确"重复算量图层，不提取" |
| `现场实际间隔柱定位` | 1 | 施工定位层 |

孔洞 36→268 是这些越界件带进来的（含一个 3512m² 的场地级多边形）。
登记的 133/36/133 与画像 notes 逐层对得上，**声明值是对的，图层过滤漏了**。

### 结论三：canada_ifc 是源图改版，不是代码回归

案例指纹与现行源图不是同一修订（LWPOLYLINE 779→766、编号层 749→767、
多出 Defpoints 10），而 `8c700df`(09-02)、`49da243`(09-19)、HEAD 三个代码
版本读现行文件**都得 766**。即 765 来自 09-02 之前的旧版图；案例应按现行
修订重新登记（旧值写进 notes 保留血缘）。

### 水星 15 件的真根因（比第六节的判断更细）

第六节记的是"把兜闭合判定钳到 0.01mm"。逐条复算后是**三件事叠在一起**：

1. `_point_on_segment` 的端点余量写成 `dot <= length_sq + tolerance`——
   `dot`/`length_sq` 是面积量纲、`tolerance` 是长度，量纲错配。实测
   末点越界 0.0309mm 需要 **19.9** 的"容差"才能判成落在边上，这条判据
   实际上是作废的；改成 `tolerance * 边长` 才等价于"距线段 ≤ tolerance"。
2. 49da243 把"末点落在已有边上 ⇒ 兜成闭合"这条**判定**也钳到 0.01mm，
   0.0309mm 的收口残点从此判不出。
3. 但**不能**把判定放宽回 `closed_tolerance`：fuzhou 声明 1000mm，放宽后
   1000x1000 的闭环会被当成"末点落在已有边上"裁成三角形
   （`test_large_closure_tolerance_does_not_collapse_closed_polyline` 抓到的）。
   所以残点判定用制造噪声尺度 `min(画像容差, 0.1mm)`——0.03mm 级残点在
   噪声内，0.1mm 以上是刀缝/加工公差量级，再大就不是残点而是真缺口。

另外补一条：实体自带闭合标记时（`LWPolyline.closed`），顶点表就是环，
裁剪只会伤它——这类实体只做去重（该用例的矩形正是被裁成三角形的现场）。

## 十五、用户发现"台面板边缘线没了"——圆弧覆盖判定的两处坑

用户看定稿原位 DXF 后指出：**台面板的边缘线没有了**。核对属实，而且是本轮
新写的"圆弧如实复写"引入的：把边界拆成"圆弧 + 剩余折线"时，两处判定写错，
把不该吃的直线段吃掉了。

| 坑 | 现象 | 原因 | 修法 |
|---|---|---|---|
| 覆盖判定 | 台面左右两条长边、底边、25mm 台阶全部消失（XST-1 轮廓覆盖只剩 82.6%） | 用"到圆弧**采样折线**的距离 ≤1.5mm"判顶点是否属于圆弧：r25、32 段采样时第一个采样点离端点就有 1.3mm，于是圆弧**端点**与相邻直线的端点一起被判成"在圆弧上"，整段直线被吃掉 | 改成按**角度区间**判定（`_vertex_inside_arc`）：半径对得上 + 角度严格在起止角之间（留 0.5° 余量），端点归相邻直线 |
| 环形收尾 | 修完上一处后，XST-4 仍丢一段（98.8%），XST-1 仍丢左边整条 | 折线段按线性扫描生成：环首尾相接的那一段被拆成"末尾一个点（<2 点被丢弃）+ 开头一段" | 从一个"覆盖 → 未覆盖"的边界起算（`_ring_runs_outside_arcs` 里按 `(index+1) % n` 扫描），保证不跨越列表首尾 |

### 复算验收

把写出的 OUTER 实体拼回几何、按 5mm 采样比对识别轮廓：

| 零件 | 输出实体 | 覆盖 |
|---|---|---|
| XST-4 台面 | ARC ×3（r25 ×2 + r5）+ PL5 + PL2 + PL2 | 98.8% |
| XST-1 台面 | ARC ×2（r25 ×2）+ PL4 + PL2 | 98.8% |
| XST-2/3/5/6 立板 | 各一条闭合 PL5 | 100% |
| HOLES | 4 个 CIRCLE | — |

余下 1.2%（每个台面 6 个采样点）落在两处 r25 圆角上，实测间距 1.4mm 级，
正是"写真圆弧"与"识别环的展平折线"之间的差——**输出比识别环更准**，不是缺口。

测试：`tests/test_dxf_writer_source_curves.py` 2 例通过；全量快测
**507 passed / 7 skipped**；基准 **7 通过 / 0 失败 / 4 跳过**。
定稿产物已按修复后的写入端重出（`*_定稿.*`）。

### 经验（已写进 AGENTS.md）

轮廓上"哪一段是圆弧"的判定，距离/采样法在两个地方都会翻车：端点归属与环形
收尾。**角度区间 + 环形扫描**是正解；验收要用"写出的实体拼回几何后与识别轮廓
比覆盖率"，不能只看实体个数。
