### 3. L 型面板 closed=False 检测

**问题**：86 条 LWPOLYLINE 的 `closed` 属性为 False，但视觉上是封闭 L 型台面。

**分析**：
- 64 条：首点在倒数第二位置重复（`first ≈ coords[-2]`），末点是多余顶点
  - 例：`[0, 1, 2, 3, 4, 5, 0(=6), 7]`，应截断到点6
- 16 条：末点等于第二点（`last ≈ coords[1]`），需提取循环
  - 例：`[0, 1, 2, 3, 4, 5, 6, 1(=7)]`，应提取 [1..7] 作为闭合环

**修复**：`try_close_polyline()` 四层兜底：
1. 清理连续重复点（<0.01mm）
2. 首点≈内部点 → 截断
3. 末点≈内部点 → 提取循环
4. Force-close：追加首点

**结果**：80 条全部恢复，面板从 1178 → 1258。

### 4. 混合大板尺寸排板策略

**问题**：9 块 F 厨房 L 型面板（1621×2540）在 3200×1600 中无法放置，
即使旋转 90° 也超 21mm。其余 1249 块可放入 3200×1600。

**用户需求**：9 块 F 厨房用 3200×1625，排完后剩余空间填入其他面板，
减少总板数。

**方案**：统一用 3200×1625 排全部 1258 块板，输出时标记含 F 厨房的板
为 3200×1625，其余为 3200×1600。由于 1625 > 1600 仅差 25mm，
引擎自然利用多出的空间，不会额外浪费板材。

## 关键经验

### 1. 制图差异导致编号策略完全不同
- CGR45：独立"编号"层 + TEXT → containment-first 匹配
- 水星项目户型：layer 0 + MTEXT 户型标签 → nearest-match + sequence
- 同一套 `read_dxf` 接口需要兼容多种制图风格

### 2. closed=False 不等于非封闭
- CAD 制图习惯：L 型用多段线画完回到起点，但 `closed` 属性不设 True
- 检测策略：先清重复点，再检测首/末点与内部点的重合关系
- 不能简单 `force-close`（追加首点），会创建错误几何

### 3. PowerShell here-string 的转义陷阱
- `@"..."@` 中的 `\\` 传给 Python 可能变成 `\\\\`
- 正则 `\\s` → `\\\\s` 匹配的是 literal `\s` 而非 whitespace
- 安全做法：Python Unicode escape（`\uXXXX`）或单独 `.py` 文件

### 4. 大板尺寸策略
- 少量超尺寸面板不应该换全部大板规格
- 混合尺寸 + 剩余空间回填 = 最少浪费
- 实现上：统一用最大尺寸排板，输出时按面板归属标记

### 5. 1258 块面板的性能
- 单 config 贪心：~286s
- 4 configs 贪心 + 30s LNS：~828s
- 默认 configs（6+）+ 60s LNS × 2 trials：超 30 分钟
- 大规模排板应先用单 config 贪心快速出结果，再逐步加优化
