# 工作日志 2026-09-23

## 主题

冷启动可复现性：把"依赖历史运行结果"的地方显式化，并修复由此暴露的识图缺陷。

## 背景

用户手动清空了 `output/` 下的历史运行目录（`output/<时间戳>_<项目>/`），
目的是验证**系统在没有以往运行结果参考时，也能识图和排板**。这次冷启动
测试直接暴露了三件事：

1. `scripts/check_output_cases.py` 的 6 个回归 case 输入全部指向 `output/`
   下的编号 DXF，而该目录被 `.gitignore` 的 `output/*_*/` 忽略 → 输入失效、
   历史结论无法复现；
2. 运行时默认会命中「已验证模板」，直接复刻历史排板布局、跳过排板算法；
3. CGR45 读图的孔洞数从画像期望的 306 掉到 153，一直没被拦住。

## 已完成

### 1. 修复孔洞被静默丢弃（`src/drawing_profile.py`）

`_extract_profile_panels()` 里 `profile.build_hierarchy` 分支有两个叠加缺陷：

- `_build_part_hierarchy()` 返回的 `children` 是**按面积降序排列后的序号**，
  旧代码却用 `accepted_candidates[child_index]` 去取（原始顺序），取错了元素；
  对照 `dxf_reader.read_dxf` 的正确写法是 `hierarchy[child_index]["poly"]`；
- 取到子级后还要求 `candidate["classification"]["role"] == "hole"` 二次过滤，
  而图层弱化后分类器常把被包含的闭合多段线判成 `panel`（理由 `topology:outer`），
  于是这些孔洞被整体丢弃。

修复：子级一律按 `hierarchy[...]` 取值，并且**被父轮廓直接包含的子轮廓在几何上
就是孔洞**，不再用分类器 role 二次过滤。

CGR45 实测（`tests/fixtures/dxf/CGR45final.dxf`）：

| 指标 | 修复前 | 修复后 | 画像期望 |
|---|---:|---:|---:|
| panels | 203 | 203 | 203 |
| holes | 153 | **306** | 306 |
| numbers | 203 | 203 | 203 |

影响面：修复前这 153 个孔的面积没有扣除（出材率被高估），且排板/编号 DXF
不会画出这些孔（下料会漏孔）。

### 7. 修画像排序的"同分静默误配"（第 2 项）

**问题**：`rank_profiles` 只按"图层名是否命中"打分，对"0 层 + 编号层 + 建层级"
这一类图纸，`cgr45` 与 `canada3l` **同为 105 分**；并列后 `results.sort` 稳定排序
按 `load_profiles` 的字典序取第一个 → 冷启动时 CGR45 被判成 `canada3l` 画像。
案例库（`validated_cases`）正好掩盖了这个缺陷。

**修复**（三处）：

1. `DrawingProfile` 新增可选 `fingerprint` 字段（已验证图纸指纹）；
2. `drawing_profile.fingerprint_similarity()` 成为**唯一实现**（0-100：图层集合
   50 / 实体集合 20 / 线型集合 15 / 结构布尔与版本 20），`case_library.case_similarity`
   改为委托它，消除两处各写一份的问题；
3. 排序改为**分层**：指纹相似度 ≥ `FINGERPRINT_MATCH_THRESHOLD=60` 的画像进入
   优先层（+100 偏移 + 相似度×0.5），低于阈值完全不加分；并且**同分时打印
   并列告警**，不再静默按文件名字典序选。

**关键细节**：结构性布尔特征必须"不一致就扣分"。只做集合 Jaccard 时
countertop2（无圆孔）与 cgr45（153 个圆孔）的指纹相似度仍有 64.8 分——高于阈值，
导致 cgr45 画像抢走 countertop2 的图纸。因此把 `has_circle` 不一致改为 −15
（`has_lwpolyline` / `has_line` 为 −5），两者相似度降到 49.8，安全低于阈值。

**验证**（冷启动，`use_case_library=False`）：

| 样本 | 修复前 | 修复后 |
|---|---|---|
| `CGR45final.dxf` | canada3l ❌ | **cgr45**（255.0 分）✅ |
| `countertop2.dxf` | 无案例库时 4 个画像并列 105 分 | **countertop2**（指纹层命中）✅ |
| `mercury_numbered_原位.dxf` | — | None（编号后 DXF，无匹配画像）✅ |

已回填 `cgr45.json` 与 `countertop2.json` 的 `fingerprint`（与
`validated_cases` 同源，按 fixture 哈希核对过；mercury 的案例指纹对应原始图纸、
与本地编号后样本哈希不一致，**不回填**）。

### 8. 水刀/激光引擎角度策略改造（第 3 项第 1 步）

**先做了隔离实验**（CGR45final，203 件，3200x1800，同一进程内直接调引擎）：

| 配置 | 板数 | 出材率 | 耗时 |
|---|---:|---:|---:|
| 4 角 (0/90/180/270) | 54 | 67.55% | 8.7s |
| 24 角 (15° 网格 = 旧 quick 默认) | 61 | 59.80% | 35.4s |
| 72 角 (5° 网格 = 旧 full 默认) | 61 | 59.80% | 104.3s |
| 4 角 + 4 轮排序 | 54 | 67.55% | 33.8s |
| 24 角 + 4 轮排序 | 60 | 60.80% | 129.6s |

实验结论（推翻了"角度不够→密度不够"的直觉假设）：

1. **细化角度是负收益**：24 角与 72 角板数相同（61），5° 白烧 69s；角度越多反而比
'
   '   4 角差 7 张板 —— 贪心近视，更多旋转让零件先被摆歪、堵住后续空间；
2. **多轮排序不是杠杆**：4 角 1 轮与 4 轮同为 54 张，成本却翻 4 倍；
3. 因此瓶颈在**放置准则**（纯 bottom-left `(y, x)`），不在角度数量。

**改造**（`src/deepnest_engine.py`）：

- 新增 `angle_mode`（默认 `"edge"`）：候选角来自"让零件最长直边与板边平行"的
'
  '  角度集合，并始终包含 0/90/180/270；`"grid"` 保留旧等步长枚举，`"hybrid"` 为
'
  '  两者并集；
- 参与对齐的直边按长度降序取前 `_MAX_EDGE_ANGLES=8` 条（扫描过 2/4/8/16：8 最优，
  16 退化到 55 张）；
- 曲线件（近似圆/样条扁平化）追加 45° 粗网格兜底，判定用**最长 8 条边的周长占比
'
  '  < 0.6**，而不是"边方向数"——CGR45 有 37 个矩形零件带几十个冗余顶点，用方向数
'
  '  判定会被误当成曲线件，白加网格并多花 1 张板（55 vs 54）；
- 模块文档同时修正了"按 1 度步长枚举"的过时说明。

**效果**（CGR45final 3200x1800，CLI 端到端）：

| 路径 | 改造前 | 改造后 |
|---|---|---|
| `--process waterjet --quick` | 61 张 / 59.80% / 35.2s | **54 张 / 67.55% / 10.0s** |
| `--process waterjet`（full） | 61 张 / 59.80% / 104.3s | **54 张 / 67.55% / 10.0s** |

与桥切引擎（52 张 / 70.15%）的差距从 9 张缩到 **2 张**。

新增测试 6 个（`tests/test_deepnest_engine.py`）：轴对齐矩形=4 角、旋转 30° 跟随
'
'零件方向、冗余顶点不引入新方向、曲线件触发 45° 兜底、`grid` 模式等价旧行为、
'
'无 `part` 时保持旧行为。benchmark 新增 `cgr45_nest_waterjet`（slow，
'
'`max_sheets=54 / min_yield=65.0 / max_seconds=120`）。

### 9. 放置准则与候选生成系统排查（第 3 项第 2 步，结果为中性）

角度策略修好后，水刀引擎在 CGR45 上是 54 张，桥切引擎是 52 张。为定位这 2 张
差距，逐个隔离变量（同图纸、同种子、单进程直调引擎）：

| 变量 | 取值 | 板数 |
|---|---|---:|
| 打分准则 | bottom_left / skyline / column / contact | 54 / 54 / 55 / 54 |
| `_MAX_VALID_PER_ANGLE` | 4 / 8 / 16 | 54 / 54 / 54 |
| 候选顺序 | legacy（y,x 升序）/ sorted（按准则排序后截断） | 54 / 54 |
| 凹角锚定候选 | 关闭 / 开启 | 54 / 54（开启更慢 +8s） |
| 多排序 trials | 1 轮 / 4 轮 | 54 / 54 |
| 低填充板重排 | 关闭 / T=0.6 / 0.75 / 0.85 | 54 / 54 / 54 / 54 |

**结论：这张图纸的板数由贪心的"当前板放不下就换板、永不回头"结构决定，
不是由任何单个参数决定。** 要再降板数必须改核心循环：

1. 照桥切引擎的做法，**批量构建候选多边形**（`shapely.polygons` 一次 C 调用）
   并**只在最后统一滑动**（现在每个候选都跑一次二分滑动），
   同时把候选按准则排序后取前 N 个（已实现为 `candidate_order="sorted"`，但
   单独打开不足以改变结果）；
2. 或实现真正的 **LNS/跨板重排**（桥切引擎 `_lns_improve` 的对应物）。

**顺带发现一个死参数**：`nest_parts_deepnest(improve_budget=..., configs=...)`
两个参数**从未被使用**，而 `workflow.py` 在水刀路径上传了 `improve_budget=budget`
（CLI 默认 180s）——即用户要求的长时搜索被**静默丢弃**。已在入口 docstring
写明"尚未实现 LNS、时间预算不生效"，并保留参数以维持与桥切引擎同构的签名。

**保留下来的东西**：`score_mode` / `candidate_order` / `use_reflex` /
`low_fill_rework` / `low_fill_threshold` 全部作为**显式实验入口**保留，默认值
是当前最优口径（`bottom_left` / `legacy` / 关闭 / 关闭）；`low_fill_rework`
按计划 Step 2 实现并带"只在板数减少时接受"的契约（
`test_low_fill_rework_never_increases_sheet_count`），等有碎片板案例
（如东莞奥特莱斯2 的 sheet 7）时可直接开启验证。

### 10. 口径与场景更正（用户指出）

**参数语义**：大板标称尺寸就是 **3200x1800**。让尺 30mm 与刀缝 5mm 是**独立工艺
参数**，不能并入大板尺寸——我此前把 outlets2 的排板用例写成 `sheet=[3230, 1830]`
（等于把"3200x1800 + 让尺 30"当成板尺寸），已更正为 `sheet=[3200, 1800]` +
`kerf_mm=5.0` + `sheet_oversize=[30, 30]`。仓库里其他 `3230x1830` 出现处
（加拿大3L 的 worklog 与 `check_output_cases.py`）是该项目的实际生产板型，属正常。

**加工场景**：只有**不规则规格板**才用水刀/激光；**台面板以圆盘锯（桥切）为主**。
CGR45 是 203 件台面板 → 主路径是桥切。因此：

- 把 CGR45 当水刀案例优化、追"水刀 54 张 vs 桥切 52 张"是**跨工艺的错误对比**；
- 第 9 节那些"对 CGR45 中性"的水刀侧开关，结论只适用于"水刀引擎处理多边形件"
  这一非目标组合，**不能外推到异形件**；
- 角度策略改造（边对齐）仍保留：异形件的价值就在斜边/弧边，但收益幅度必须在
  异形样本上重测。

**由此确认的两条主线**：

1. **桥切是主战场，而它的 180s LNS 目前零收益**：`cg45` 同图纸
   `--quick` 纯贪心 52 张 / 70.15% / 23.9s，full + LNS 180s 同样 52 张 / 70.15% /
   227.4s。面积下界 37 张，说明不是已到极限，而是 `_lns_improve` 没产生任何改进。
2. **水刀缺异形金标准**：outlets2（1109 件异形，下界 39 张）是真实水刀案例，样本已丢；
   已登记为 `outlets2_nest_waterjet`（pending，skipped），样本补齐前水刀侧无法验证。

**benchmark 增强**：排板 runner 现在支持 `kerf_mm` / `sheet_oversize`，并新增
**桥切生产口径**用例 `cgr45_nest_bridge_kerf`（标称 3200x1800 + 刀缝 5 + 让尺 30）：
实测 **52 张 / 70.15% / 19.0s**，与标称口径同板数（让尺正好容纳刀路）。
